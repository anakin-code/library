共通のapi.fetchで403を処理する

今使っているapi.fetch(...)の中に、BAN時の処理を追加する。

import { signOut } from "aws-amplify/auth";

export const apiFetch = async (
  input: RequestInfo | URL,
  init?: RequestInit
): Promise<Response> => {
  const response = await fetch(input, init);

  if (response.status === 403) {
    let message = "このアカウントは利用停止されています";

    try {
      const errorData = await response.clone().json();

      if (typeof errorData.message === "string") {
        message = errorData.message;
      }
    } catch {
      // JSONではない場合は標準メッセージを使用
    }

    if (message.includes("利用停止")) {
      sessionStorage.setItem("loginErrorMessage", message);

      await signOut();

      window.location.href = "/login";
    }
  }

  return response;
};

重要なのはこれ。

await signOut();
window.location.href = "/login";

BANされたユーザーが持っているCognitoのログイン状態を消して、ログイン画面に戻す。

2. 既存のuseApiに入れる場合

今のWEB層では、画面からこのように呼んでいたはず。

const response = await api.fetch(requestUrl);

そのため、Home.tsxやNeedList.tsxを全部変更するのではなく、useApiの中を変更する。

イメージはこう。

import { fetchAuthSession, signOut } from "aws-amplify/auth";

export const useApi = () => {
  const apiFetch = async (
    url: string,
    options: RequestInit = {}
  ): Promise<Response> => {
    const session = await fetchAuthSession();
    const accessToken =
      session.tokens?.accessToken?.toString();

    const response = await fetch(url, {
      ...options,
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${accessToken}`,
        ...options.headers,
      },
    });

    if (response.status === 403) {
      const clonedResponse = response.clone();

      try {
        const errorData = await clonedResponse.json();

        if (
          errorData.message ===
          "このアカウントは利用停止されています"
        ) {
          sessionStorage.setItem(
            "loginErrorMessage",
            errorData.message
          );

          await signOut();

          window.location.href = "/login";
        }
      } catch (error) {
        console.error("403レスポンスの解析に失敗しました", error);
      }
    }

    return response;
  };

  return {
    fetch: apiFetch,
  };
};

こうすれば、既存のコードはそのままでいい。

const response = await api.fetch(requestUrl);

一覧取得でも、詳細取得でも、投稿でも、コメントでも、BANユーザーなら共通処理でログアウトされる。

3. ログイン画面でメッセージを表示する

ログインページでsessionStorageのメッセージを読む。

const [errorMessage, setErrorMessage] = useState("");

useEffect(() => {
  const message =
    sessionStorage.getItem("loginErrorMessage");

  if (message) {
    setErrorMessage(message);
    sessionStorage.removeItem("loginErrorMessage");
  }
}, []);

MUIならこう表示する。

{errorMessage && (
  <Alert severity="error" sx={{ mb: 2 }}>
    {errorMessage}
  </Alert>
)}

これでBANされたユーザーがAPIを操作すると、ログイン画面に戻って、

このアカウントは利用停止されています

と表示される。

4. 各画面にはBAN処理を書かない

これは避けた方がいい。

if (response.status === 403) {
  await signOut();
  navigate("/login");
}

これをHome、NeedList、ContentDetail、CommentSectionなど全部に書くと、修正漏れが起きる。

今回なら、

useApi
または
apiClient.ts

の1か所だけ直す。

5. 403全部をBAN扱いしない

403はBAN以外でも使われる可能性がある。

例えば、

他人の投稿を編集しようとした
管理者権限がない
削除権限がない

でも403になる。

だから、ステータスだけでなく、Serverから専用コードを返す方が安全。

Server側をこうする。

{
  "status": 403,
  "code": "ACCOUNT_BANNED",
  "message": "このアカウントは利用停止されています"
}

Client側はこう判定する。

if (
  response.status === 403 &&
  errorData.code === "ACCOUNT_BANNED"
) {
  sessionStorage.setItem(
    "loginErrorMessage",
    errorData.message
  );

  await signOut();

  window.location.href = "/login";
}

文字列の一致よりACCOUNT_BANNEDで判定する方がいい。

今回の修正場所
Server
UserにbanFlg追加
UserInfoServiceでbanFlg確認
ACCOUNT_BANNEDの403を返す

Client
useApiまたはapiClientの共通fetchを修正
403 + ACCOUNT_BANNEDならCognito signOut
/loginへ移動
Login画面で利用停止メッセージ表示

つまり、クライアント側の中心修正は**HomeやNeedListではなく、JWTを付けている共通のfetch部分**。
