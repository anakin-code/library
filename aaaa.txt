5. TipRepository

既存の ContentRepository の置き換え。
今の ContentRepository は JpaSpecificationExecutor<Content> を継承していて、投稿一覧をいいね数順・作成日順で取るQueryも持っている。
新ERでは contents ではなく tips になるので、ContentRepository を TipRepository に置き換える。

package simplex.pj148.skippy.server.repository;

import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import simplex.pj148.skippy.server.entity.Tip;

import java.util.List;
import java.util.Optional;

public interface TipRepository extends JpaRepository<Tip, Long> {

    Optional<Tip> findByTipId(Long tipId);

    /**
     * 公開中のTip一覧
     * deleteFlgをEntityに残す場合
     */
    Page<Tip> findByDeleteFlgFalse(Pageable pageable);

    /**
     * ユーザーのTip一覧
     */
    Page<Tip> findByUser_UserIdAndDeleteFlgFalse(
            Long userId,
            Pageable pageable
    );

    /**
     * カテゴリ指定あり・なしでTip一覧を作成日順に取得
     */
    @Query("""
            SELECT t
            FROM Tip t
            WHERE t.deleteFlg = false
              AND (:categoryId = 0 OR t.category.categoryId = :categoryId)
            ORDER BY t.createdTime DESC
            """)
    Page<Tip> findSelectedTipsSortedByCreatedTime(
            Pageable pageable,
            @Param("categoryId") Long categoryId
    );

    /**
     * カテゴリ指定あり・なしでTip一覧を気になる数順に取得
     */
    @Query("""
            SELECT t
            FROM Tip t
            LEFT JOIN TipInterest ti ON ti.tip = t
            WHERE t.deleteFlg = false
              AND (:categoryId = 0 OR t.category.categoryId = :categoryId)
            GROUP BY t
            ORDER BY COUNT(ti) DESC, t.createdTime DESC
            """)
    Page<Tip> findSelectedTipsSortedByInterestCount(
            Pageable pageable,
            @Param("categoryId") Long categoryId
    );

    /**
     * Needに紐づくTip一覧
     */
    List<Tip> findByNeed_NeedsIdAndDeleteFlgFalse(Long needsId);
}
注意

新ER図に delete_flg がないなら、上の deleteFlg 系は消す。
でも既存Entityでは Content, Need, Comment に deleteFlg があるので、実装上は残した方が安全。既存のRepositoryにも deleteFlg=false 条件が多い。

7. TipInterestRepository

今回一番重要。
既存の LikeRepository, FavoriteRepository, MyBestRepository の役割をかなり吸収する。

既存の LikeRepository では、投稿IDごとのいいね数をまとめてCOUNTするQueryがある。
新設計では「いいね」ではなく「気になる」なので、TipInterestRepository に同じような集計を作る。

package simplex.pj148.skippy.server.repository;

import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import simplex.pj148.skippy.server.entity.TipInterest;

import java.util.List;
import java.util.Optional;

public interface TipInterestRepository extends JpaRepository<TipInterest, Long> {

    /**
     * ユーザーがそのTipを気になる登録済みか
     */
    boolean existsByUser_UserIdAndTip_TipId(Long userId, Long tipId);

    /**
     * ユーザーとTipから取得
     */
    Optional<TipInterest> findByUser_UserIdAndTip_TipId(Long userId, Long tipId);

    /**
     * ユーザーの気になる一覧
     */
    List<TipInterest> findByUser_UserId(Long userId);

    /**
     * 指定Tipの気になる一覧
     */
    List<TipInterest> findByTip_TipId(Long tipId);

    /**
     * 指定Tipの気になる数
     */
    Long countByTip_TipId(Long tipId);

    /**
     * 表示中のTip群に対して、Tipごとの気になる数を一括取得
     *
     * row[0] = tipId
     * row[1] = count
     */
    @Query("""
            SELECT ti.tip.tipId, COUNT(ti)
            FROM TipInterest ti
            WHERE ti.tip.tipId IN :tipIds
            GROUP BY ti.tip.tipId
            """)
    List<Object[]> countInterestsByTipIds(@Param("tipIds") List<Long> tipIds);

    /**
     * 表示中のTip群のうち、ログインユーザーが気になる登録しているもの
     */
    List<TipInterest> findByUser_UserIdAndTip_TipIdIn(
            Long userId,
            List<Long> tipIds
    );

    /**
     * mybest登録済みのもの
     */
    List<TipInterest> findByUser_UserIdAndIsRegisterMybestTrue(Long userId);

    Optional<TipInterest> findByUser_UserIdAndTip_TipIdAndIsRegisterMybestTrue(
            Long userId,
            Long tipId
    );

    Long countByTip_TipIdAndIsRegisterMybestTrue(Long tipId);
}

これで既存の、

LikeRepository
FavoriteRepository
MyBestRepository

の多くは不要になる。

9. NotificationRepository

通知設定用。

package simplex.pj148.skippy.server.repository;

import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.stereotype.Repository;
import simplex.pj148.skippy.server.entity.Notification;

import java.time.LocalTime;
import java.util.List;
import java.util.Optional;

@Repository
public interface NotificationRepository extends JpaRepository<Notification, Long> {

    /**
     * 1つのTipInterestに対して通知設定を1つだけ許す場合
     */
    Optional<Notification> findByTipInterest_TipInterestId(Long tipInterestId);

    boolean existsByTipInterest_TipInterestId(Long tipInterestId);

    /**
     * ユーザーの通知設定一覧
     */
    List<Notification> findByTipInterest_User_UserIdAndIsActiveTrue(Long userId);

    /**
     * 毎日通知対象
     */
    List<Notification> findByFrequency_FrequencyNameAndNotificationTimeAndIsActiveTrue(
            String frequencyName,
            LocalTime notificationTime
    );

    /**
     * 毎週通知対象
     */
    List<Notification> findByFrequency_FrequencyNameAndNotificationWeekAndNotificationTimeAndIsActiveTrue(
            String frequencyName,
            Integer notificationWeek,
            LocalTime notificationTime
    );

    /**
     * 毎月通知対象
     */
    List<Notification> findByFrequency_FrequencyNameAndNotificationDayAndNotificationTimeAndIsActiveTrue(
            String frequencyName,
            Integer notificationDay,
            LocalTime notificationTime
    );
}

ただ、通知時刻を LocalTime ぴったり一致で検索すると、秒ズレで取り逃がす可能性がある。
もしDBに 09:00:00 で保存するなら問題ないけど、実装では「分単位」で丸めるのが安全。

14. 重要：Service側の呼び出しも変わる

Repositoryを変えたら、Serviceの呼び出しもこう変わる。

いいね数の旧処理
likeRepository.countLikesByContentIds(contentIds)
気になる数の新処理
tipInterestRepository.countInterestsByTipIds(tipIds)
いいね済み判定の旧処理
likeRepository.findByUser_UserIdAndContent_ContentsIdIn(userId, contentIds)
気になる済み判定の新処理
tipInterestRepository.findByUser_UserIdAndTip_TipIdIn(userId, tipIds)
wantの旧処理
wantRepository.existsByNeed_NeedsIdAndUser_UserId(needsId, userId)
共感の新処理
needEmpathyRepository.existsByNeed_NeedsIdAndUser_UserId(needsId, userId)
