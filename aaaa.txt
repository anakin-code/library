2. Repositoryに集計処理を追加

TipRepository.java

package simplex.pj148.skippy.server.repository;

import java.time.LocalDateTime;
import java.util.List;
import java.util.Optional;

import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.JpaSpecificationExecutor;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;

import simplex.pj148.skippy.server.entity.Tip;

@Repository
public interface TipRepository
        extends JpaRepository<Tip, Long>,
        JpaSpecificationExecutor<Tip> {

    Optional<Tip> findByTipId(Long tipId);

    List<Tip> findByTipIdIn(List<Long> tipIds);

    /*
     * 現在時刻から1か月以内に投稿されたTipを、
     * ユーザーごとに集計して投稿数の多い順で取得する。
     *
     * Pageableで上位10件に制限する。
     */
    @Query("""
            SELECT
                t.user.userId,
                t.user.userName,
                COUNT(t)
            FROM Tip t
            WHERE t.createdTime >= :fromDateTime
            GROUP BY
                t.user.userId,
                t.user.userName
            ORDER BY
                COUNT(t) DESC,
                t.user.userId ASC
            """)
    List<Object[]> findTopTipPostersSince(
            @Param("fromDateTime") LocalDateTime fromDateTime,
            Pageable pageable
    );
}

ここで返している Object[] は、順番として次の値です。

row[0] = userId
row[1] = userName
row[2] = Tip投稿数

ORDER BY t.user.userId ASC は、投稿数が同じ場合でも結果の順序が毎回変わらないようにするためです。

3. Serviceを追加

既存の TipService に追加してください。

package simplex.pj148.skippy.server.service;

import java.time.LocalDateTime;
import java.util.List;

import org.springframework.data.domain.PageRequest;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import lombok.RequiredArgsConstructor;
import simplex.pj148.skippy.server.controller.dto.response.TipPosterRankingResponseDto;
import simplex.pj148.skippy.server.repository.TipRepository;

@Service
@RequiredArgsConstructor
public class TipService {

    private final TipRepository tipRepository;

    /*
     * 現在時刻から1か月以内のTip投稿数Top10を取得する。
     */
    @Transactional(readOnly = true)
    public List<TipPosterRankingResponseDto> findMonthlyTopTipPosters() {

        LocalDateTime oneMonthAgo = LocalDateTime.now().minusMonths(1);

        List<Object[]> rankingRows =
                tipRepository.findTopTipPostersSince(
                        oneMonthAgo,
                        PageRequest.of(0, 10)
                );

        return rankingRows.stream()
                .map(row -> TipPosterRankingResponseDto.builder()
                        .userId((Long) row[0])
                        .userName((String) row[1])
                        .tipCount((Long) row[2])
                        .build())
                .toList();
    }
}

基準時刻はこの部分です。

LocalDateTime oneMonthAgo = LocalDateTime.now().minusMonths(1);

たとえば現在が 2026-07-17 10:00 なら、

2026-06-17 10:00 以降

のTipだけを集計します。

package simplex.pj148.skippy.server.controller;

import java.util.List;

import org.springframework.http.ResponseEntity;

import org.springframework.web.bind.annotation.RequestMapping;

@RestController
@RequestMapping("/api/tips")
@RequiredArgsConstructor
public class TipController {

    private final TipService tipService;

    /*
     * 直近1か月のTip投稿数Top10

処理の流れ
現在時刻
  ↓ minusMonths(1)
1か月前の日時を算出
  ↓
createdTimeが1か月前以降のTipだけ取得
  ↓
userIdごとにGROUP BY
  ↓
COUNT(t)で投稿数を計算
  ↓
投稿数の多い順
  ↓
PageRequest.of(0, 10)で上位10人

これは「今月の1日から現在まで」ではなく、現在時刻からさかのぼって1か月間のランキングです。













spring.jpa.hibernate.ddl-auto=update

ただし、ユーザーEntityに次のように追加しただけでは、既存データがある場合に安全とは限りません。

@Column(nullable = false)
private boolean banFlg = false;

PostgreSQL側で新しい列を NOT NULL として追加すると、既存行には値がないため、テーブル更新に失敗する可能性があります。

一番安全な方法

先にPostgreSQLで列を追加します。

ALTER TABLE users
ADD COLUMN ban_flg BOOLEAN NOT NULL DEFAULT FALSE;

テーブル名やカラム名は、実際のEntityに合わせてください。たとえばフラグ名が isAllowed なら、

ALTER TABLE users
ADD COLUMN is_allowed BOOLEAN NOT NULL DEFAULT FALSE;

その後、Entityを次のようにします。

@Column(name = "ban_flg", nullable = false)
private boolean banFlg = false;

これなら、

既存ユーザー → false
新規ユーザー → Java側で false
SQLから直接登録したユーザー → DBのデフォルトで false

になります。

application-local.properties

基本的には次の状態で大丈夫です。

spring.jpa.hibernate.ddl-auto=update

spring.sql.init.mode=never
spring.jpa.defer-datasource-initialization=false

spring.sql.init.mode=never は、schema.sql や data.sql を自動実行しない場合に有効です。

画像ではコメントアウトされているので、初期化SQLを使わないならコメントを外して構いません。

spring.jpa.hibernate.ddl-auto=update
spring.sql.init.mode=never
spring.jpa.defer-datasource-initialization=false
DataInitializerについて

今のコードは、

if (userRepository.count() > 0) {
    return;
}

となっているため、ユーザーが1件でも存在すると、カテゴリー・職位・所属などの初期化も全部スキップされます。

ただし、今回の「ユーザーにフラグ列を追加する」処理には、DataInitializer は基本的に関係ありません。既存ユーザーのフラグはDBの ALTER TABLE で埋めるのが確実です。

結論

今回のおすすめはこれです。

spring.jpa.hibernate.ddl-auto=update
spring.sql.init.mode=never
spring.jpa.defer-datasource-initialization=false

加えてDBで一度だけ実行します。

ALTER TABLE users
ADD COLUMN ban_flg BOOLEAN NOT NULL DEFAULT FALSE;
