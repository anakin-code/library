
1. Pagination を import した

修正後は MUI の Pagination を使うために、import に追加している。

import {
  Container,
  Box,
  Avatar,
  Typography,
  Tabs,
  Tab,
  Button,
  TextField,
  CircularProgress,
  Pagination,
} from "@mui/material";

これは画面下にページ番号を出すため。

2. PageResponse 型を追加した

サーバーが Page<ContentShowResponseDto> を返すと、フロントには単なる配列ではなくこういう形で返る。

{
  "content": [...],
  "totalPages": 3,
  "totalElements": 45,
  "number": 0,
  "size": 20,
  "first": true,
  "last": false
}

だから、それを受け取る型として追加している。

type PageResponse<T> = {
  content: T[];
  totalPages: number;
  totalElements: number;
  number: number;
  size: number;
  first: boolean;
  last: boolean;
};

一番使っているのはこの2つ。

content
totalPages

content が実際の投稿配列。
totalPages がページ数。

3. 投稿用・いいね用のページ状態を追加した

追加したstateはここ。

const [myContentsPage, setMyContentsPage] = useState(0);
const [myContentsTotalPage, setMyContentsTotalPage] = useState(0);

const [likedContentsPage, setLikedContentsPage] = useState(0);
const [likedContentsTotalPage, setLikedContentsTotalPage] = useState(0);

意味はこう。

state	意味
myContentsPage	自分の投稿の現在ページ。0始まり
myContentsTotalPage	自分の投稿の総ページ数
likedContentsPage	いいね一覧の現在ページ。0始まり
likedContentsTotalPage	いいね一覧の総ページ数

注意点として、Springのpageは0始まり。
でも MUI の Pagination は 1始まり。
だから後で page + 1 や value - 1 をしている。

4. 投稿取得処理を関数化した

ここがかなり大事。

const fetchMyContents = (userId: number, page: number): void => {
  setIsLoading(true);

  api
    .fetch(`/api/users/${userId}/contents?page=${page}&size=20`)
    .then((res: Response): Promise<PageResponse<Content>> => res.json())
    .then((data: PageResponse<Content>): void => {
      setMyContents(data.content);
      setMyContentsTotalPage(data.totalPages);
      setIsLoading(false);
    })
    .catch((error: Error): void => {
      console.error(error);
      setIsLoading(false);
    });
};

前はたぶん、直接 api.fetch(...) を書いていた。
修正後は、何ページ目を取るかを引数で渡せる関数にした。

変わったURLはここ。

/api/users/${userId}/contents?page=${page}&size=20

これで、2ページ目を押したら、

/api/users/1/contents?page=1&size=20

を取りに行ける。

そしてレスポンスから、

setMyContents(data.content);
setMyContentsTotalPage(data.totalPages);

している。

つまり、data 全体を一覧として使うのではなく、data.content を投稿一覧として使うように変えた。

5. いいね取得処理も関数化した

いいね側も同じ。

const fetchLikedContents = (userId: number, page: number): void => {
  setIsLoading(true);

  api
    .fetch(`/api/users/${userId}/likedContents?page=${page}&size=20`)
    .then((res: Response): Promise<PageResponse<Content>> => res.json())
    .then((data: PageResponse<Content>): void => {
      setLikedContents(data.content);
      setLikedContentsTotalPage(data.totalPages);
      setIsLoading(false);
    })
    .catch((error: Error): void => {
      console.error(error);
      setIsLoading(false);
    });
};

こっちはURLがこれ。

/api/users/${userId}/likedContents?page=${page}&size=20

つまり「いいねした投稿」もページごとに取得できるようにした。

6. 初回表示時は投稿の1ページ目を取得するようにした

useEffect の中でプロフィールを取った後に、投稿の0ページ目を取っている。

useEffect((): void => {
  api
    .fetch("/api/me/profile")
    .then((res: Response): Promise<User> => res.json())
    .then((data: User): void => {
      setProfile(data);
      setEditProfile(data);

      setMyContentsPage(0);
      fetchMyContents(data.userId, 0);
    })
    .catch((error: Error): void => {
      console.error(error);
      setIsLoading(false);
    });
}, []);

ここでやってることは、

setProfile(data);
setEditProfile(data);

でプロフィール情報を保存。

その後、

setMyContentsPage(0);
fetchMyContents(data.userId, 0);

で 自分の投稿の1ページ目 を取得。

7. タブ切り替え時の処理を修正した

handleMenuChange で、タブを変えたときにページもリセットしている。

投稿タブの場合。

case "posts":
  if (profile?.userId) {
    setMyContentsPage(0);
    fetchMyContents(profile.userId, 0);
  }
  break;

いいねタブの場合。

case "liked":
  if (profile?.userId) {
    setLikedContentsPage(0);
    fetchLikedContents(profile.userId, 0);
  }
  break;

これをしないと、例えば投稿タブで3ページ目を見たあと、いいねタブに移ったときに変なページから始まる可能性がある。

だから、タブを切り替えたら基本は 0ページ目に戻す。

8. ページ番号を押したときの処理を追加した

投稿用。

const handleMyContentsPageChange = (
  _event: ChangeEvent<unknown>,
  value: number
): void => {
  const nextPage = value - 1;
  setMyContentsPage(nextPage);

  if (profile?.userId) {
    fetchMyContents(profile.userId, nextPage);
  }
};

いいね用。

const handleLikedContentsPageChange = (
  _event: ChangeEvent<unknown>,
  value: number
): void => {
  const nextPage = value - 1;
  setLikedContentsPage(nextPage);

  if (profile?.userId) {
    fetchLikedContents(profile.userId, nextPage);
  }
};

ここで大事なのがこれ。

const nextPage = value - 1;

MUIのPaginationは画面上だと、

1 2 3

だけど、Spring Bootに送るページ番号は、

0 1 2

だから value - 1 にしている。

9. 投稿一覧の下に Pagination を追加した

投稿一覧の表示部分は、今まで通り myContents.map(...) で ContentCard を並べている。

{myContents.map((content: Content) => (
  <ContentCard
    key={content.contentsId}
    content={content}
  />
))}

その下にこれを追加した。

{myContentsTotalPage > 1 && (
  <Box sx={{ display: "flex", justifyContent: "center", mt: 2, mb: 4 }}>
    <Pagination
      count={myContentsTotalPage}
      page={myContentsPage + 1}
      onChange={handleMyContentsPageChange}
      color="primary"
      shape="rounded"
    />
  </Box>
)}

意味はこう。

count={myContentsTotalPage}

総ページ数。

page={myContentsPage + 1}

MUIは1始まりなので、表示用に +1。

onChange={handleMyContentsPageChange}

ページ番号を押したら、次のページを取りに行く。

10. いいね一覧の下にも Pagination を追加した

いいねも同じ。

{likedContentsTotalPage > 1 && (
  <Box sx={{ display: "flex", justifyContent: "center", mt: 2, mb: 4 }}>
    <Pagination
      count={likedContentsTotalPage}
      page={likedContentsPage + 1}
      onChange={handleLikedContentsPageChange}
      color="primary"
      shape="rounded"
    />
  </Box>
)}

これで、いいね一覧も2ページ目以降に行ける。

結論

この修正は、自分の投稿といいね一覧で、サーバーから返ってくる Page 形式を正しく使うための修正。

今まではサーバーが size=20 で返す1ページ目だけを表示していた。
修正後は、ページ番号を押すたびに、

page=0
page=1
page=2

をクライアントから送るので、21件目以降の投稿も表示できる。




まず全体像

今回の流れはこれ。

MyPage.tsx
  ↓
/api/users/1/contents?page=0&size=20
  ↓
Spring Boot
  ↓
DBから最新20件だけ取得
  ↓
{
  content: [投稿20件],
  totalPages: 3,
  number: 0,
  size: 20
}
  ↓
MyPage.tsx が content だけ表示する

つまり、ページングで大事なのはこのURL。

/api/users/${userId}/contents?page=${page}&size=20

ここで、

page=0

なら1ページ目。

page=1

なら2ページ目。

page=2

なら3ページ目。

Spring Bootのページ番号は 0始まり。

今回のコードでいうと、ページングの中心はここ
1. 現在ページをstateで持つ
const [myContentsPage, setMyContentsPage] = useState(0);
const [myContentsTotalPage, setMyContentsTotalPage] = useState(0);

const [likedContentsPage, setLikedContentsPage] = useState(0);
const [likedContentsTotalPage, setLikedContentsTotalPage] = useState(0);

これは、

今、自分の投稿の何ページ目を見ているか
今、いいね一覧の何ページ目を見ているか
全部で何ページあるか

を覚えておくため。

myContentsPage = 0 は、1ページ目を見ているという意味。

2. サーバーに「何ページ目が欲しいか」を渡す

ここが一番大事。

const fetchMyContents = (userId: number, page: number): void => {
  setIsLoading(true);

  api
    .fetch(`/api/users/${userId}/contents?page=${page}&size=20`)
    .then((res: Response): Promise<PageResponse<Content>> => res.json())
    .then((data: PageResponse<Content>): void => {
      setMyContents(data.content);
      setMyContentsTotalPage(data.totalPages);
      setIsLoading(false);
    })
    .catch((error: Error): void => {
      console.error(error);
      setIsLoading(false);
    });
};

この関数は、

fetchMyContents(1, 0);

なら、

/api/users/1/contents?page=0&size=20

を呼ぶ。

つまり、ユーザーID 1 の投稿の1ページ目を20件くださいという意味。

fetchMyContents(1, 1);

なら、

/api/users/1/contents?page=1&size=20

なので、2ページ目を20件くださいという意味。

3. サーバーから返ってくる形

サーバーは Page<ContentShowResponseDto> を返すので、フロントにはこう返ってくる。

{
  "content": [
    { "contentsId": 1, "title": "投稿1" },
    { "contentsId": 2, "title": "投稿2" }
  ],
  "totalPages": 3,
  "totalElements": 45,
  "number": 0,
  "size": 20,
  "first": true,
  "last": false
}

ここで大事なのは、

data.content

と、

data.totalPages

。

だから今回のコードでは、

setMyContents(data.content);
setMyContentsTotalPage(data.totalPages);

としている。

data.content が実際に表示する投稿一覧。
data.totalPages がページボタンの数。

4. 画面に表示するのは data.content だけ

ここ。

{myContents.map((content: Content) => (
  <ContentCard
    key={content.contentsId}
    content={content}
  />
))}

myContents には、今見ているページの20件だけが入っている。

だから、

1ページ目 → 最新1〜20件
2ページ目 → 21〜40件
3ページ目 → 41〜60件

みたいに切り替わる。

5. Paginationを押したら次のページを取りに行く

ここが次に大事。

const handleMyContentsPageChange = (
  _event: ChangeEvent<unknown>,
  value: number
): void => {
  const nextPage = value - 1;
  setMyContentsPage(nextPage);

  if (profile?.userId) {
    fetchMyContents(profile.userId, nextPage);
  }
};

MUIの Pagination は、画面上では、

1 2 3

と表示する。

でもSpring Bootに送る page は、

0 1 2

。

だから、

const nextPage = value - 1;

にしている。

例えば、画面で「2」を押したら、

value = 2

になる。

それを、

nextPage = value - 1;

で、

nextPage = 1

にする。

そして、

fetchMyContents(profile.userId, nextPage);

を呼ぶ。

つまり、

/api/users/1/contents?page=1&size=20

を取りに行く。

6. Paginationコンポーネントの意味

投稿側はここ。

<Pagination
  count={myContentsTotalPage}
  page={myContentsPage + 1}
  onChange={handleMyContentsPageChange}
  color="primary"
  shape="rounded"
/>

それぞれの意味はこう。

count={myContentsTotalPage}

全部で何ページあるか。

例えば投稿が45件で、1ページ20件なら、

totalPages = 3

なので、画面には

1 2 3

が出る。

page={myContentsPage + 1}

今選択中のページ。

Spring側は0始まりだけど、MUIは1始まりなので +1 している。

例えば、

myContentsPage = 0

なら、画面では1ページ目を選択状態にしたいので、

page={1}

になる。

onChange={handleMyContentsPageChange}

ページ番号を押したときに呼ばれる関数。

7. いいねも同じことをしている

いいね側も構造は完全に同じ。

const fetchLikedContents = (userId: number, page: number): void => {
  api
    .fetch(`/api/users/${userId}/likedContents?page=${page}&size=20`)
    .then((res: Response): Promise<PageResponse<Content>> => res.json())
    .then((data: PageResponse<Content>): void => {
      setLikedContents(data.content);
      setLikedContentsTotalPage(data.totalPages);
      setIsLoading(false);
    });
};

こっちは、

/api/users/{userId}/likedContents?page=0&size=20

を呼ぶ。

表示する配列は、

likedContents

総ページ数は、

likedContentsTotalPage

。

今までなぜ最新20件しか出なかったか

今まではたぶんこうだった。

api.fetch(`/api/users/${data.userId}/contents`)

この場合、page を送っていない。

でもサーバー側に、

@PageableDefault(size = 20)

があるから、Spring Bootは勝手にこう扱う。

page=0
size=20

だから、常に1ページ目、つまり最新20件だけ返っていた。

今回の修正では、ページを押したときに、

page=1
page=2

を送るようにした。

だから21件目以降も取れる。

返ってきた投稿だけ画面に出す。

ページ番号を何個出すか決める。

<Pagination ... />

ユーザーが2ページ目、3ページ目を押せるようにする。
